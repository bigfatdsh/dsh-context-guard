# dsh元优化插件

> 包名是 `dsh-meta-optimizer`（npm 不允许中文包名）；面板与文档里显示为 **dsh元优化插件**。

**输出前压缩**：工具结果在写进上下文**之前**再过一道压缩关卡。类型感知的结构化压缩 +
跨调用增量 + 预算内按信息量取舍，每一步都可解释、可关闭，而且**只有真省了才动手**。

> 与 [`dsh-ops`](https://github.com/T-Auto/dsh-ops) 的关系：dsh-ops 主要优化**输入侧**
> （把工具 schema、描述、系统提示词压短），并明确不做调用级去重。本插件在**输出侧**——
> 也就是"结果已经产生、token 还没付"的那一刻——做结构化压缩与跨调用增量，两者互补，
> 互不冲突（但注意：本插件与 `dsh-tool-token-optimizer` 作用在同一钩子上，建议二选一，
> 见下文「与其它插件的关系」）。

---

## 它站在哪里

挂在宿主公开契约 **`tools/post-execute`** 瀑布钩子上：工具已经跑完、结果还没写进会话与
请求的那一瞬间。

只挂这一个钩子，而且**根上挂一次就够**：`tools/post-execute` 是带作用域的事件，由
`ToolRuntime` 用 `scopeTarget(this, exec.agent)` 派发；作用域事件的路由规则是"无标签监听器
放行、有标签监听器只在标签是分发键或其祖先时放行"。因此根上这一个不带标签的监听器会收到
**所有** agent、所有会话、所有嵌套子调用（含 PTC / `run_code` 内部）的结果，不需要按 agent
各注册一份，也就不会随 agent 数量增长。

不包模型调用、不改模型目录、不碰工具注册表、不加系统提示词——**受影响的只有结果文本**。

## 三级流水线

### 1. 无损规范化（永远先跑，永远安全）

| 做什么 | 为什么 |
|---|---|
| 剥 ANSI 颜色 / 光标序列 | 终端上色只对人有用；带光标左移的序列按"终端最终可见的那一行"还原 |
| `\r` 覆盖式进度条收敛成最终一行 | `\r45%\r100% done` 只需最后一次 |
| 统一不可见字符（NBSP、零宽、BOM、方向控制符） | 不占视觉宽度，只白烧 token |
| 去行尾空白 / 压 3 行以上的连续空行 / 去首尾空行 | 纯形状 |
| 4 个以上的同字符空格串压到 2 个 | 生成出来的填充；1-3 个空格的真对齐不动 |

刻意**不做**：不把制表符换成空格、不重排缩进、不删行内空格、不合并"有内容的重复行"——
那些都会改语义（源码、`ls -l` 对齐全靠它）。

### 2. 类型感知的结构化压缩（识别不出类型就不上）

先识别、后压缩。识别不出来的内容只走第 1 级 + 第 3 级，绝不上结构化改写。

| 类型 | 怎么压 |
|---|---|
| **JSON** | 解析后重新紧凑化：去掉缩进阶梯，短容器内联。键、值、顺序一个不变 |
| **unified diff** | 每个文件的头折成一行 `# path (+a/-b)`；**增删行全部保留**（那是 diff 的全部价值）；超出的上下文行折成 `… (N lines unchanged context)`；`\ No newline at end of file` 折进上一行 |
| **git status** | 同状态的文件合并成一行，去掉逐行的 `(use "git ...")` 提示；被合并的行数记在单位上，"一共多少个文件"仍然可数 |
| **文件清单 / 目录树** | `ls -l` 权限列全一致时压掉权限列并写明；`├──`/`└──` 画线前缀压成纯缩进 |
| **带行号源码** | 行号列压到最小宽度并对齐。**代码一个字符都不动** |
| **日志** | 连续的"同一模板、只有时间戳/数字不同"的行折成 `首行 …×N (same event repeated; last: <最后一次的值>)` |
| **构建 / 测试产出** | 只有**没有任何失败信号**时才折进度行；一旦出现 error/fail/ERR 就整段不动 |
| **源码** | 只折叠"连续 3 行以上完全相同"的重复行 |
| **其它** | 折叠同一行第 3 次及以后的出现（折掉的总字符数要够本才折） |

### 3. 按比例压 + 预算内按信息量取舍

两条触发方式：**超预算**（超过该工具的 token 预算）或 **按比例**（`keepRatio`，默认压到 45%）。
都不再是"取前 N 行 + 后 N 行"，而是给每一行打分后挑选，并且**先装高信息量行**：

- **加分**：报错、失败、异常、堆栈、`expected/actual`、`:行:列`、文件路径、`exit code`、
  `not found`/`permission denied`、hunk 头、测试汇总；
- **减分**：空行、版权声明、`Please/Note/Hint` 提示、纯链接；
- 永远保留开头 6 行与结尾 8 行（命令、表头、结论、汇总都在两头）；
- 每个缺口写成 `… (N lines omitted, low-signal lines dropped)`。

### 4. 跨调用增量

同一个"工具名 + 参数"的输出第二次出现时，旧内容**还在上下文里**，再贴一遍是纯重复付费：

- 完全一样 → 一行 `(unchanged: byte-identical to the previous result of this same call, N lines, <hash>)`；
- 只是追加或局部改动 → `(delta vs the previous result of this same call: N lines unchanged)` +
  没变的只报数、变动的**逐字**给出（`- 旧行` / `+ 新行`）；
- 变化超过 40% → 照原样返回，不做增量。

模式可选：`delta`（默认）/ `identical`（只认完全相同）/ `off`。

## 三条绝不越界的承诺

1. **绝不静默丢信息**。任何"少了行"的地方都留下标记，写清楚少了几行。标记里的数字经过
   *自校验*：每个单位自带"它代表几行原文"，收尾时做加法；总量对不上就整条回滚成原文
   （宁可这一条不省，也不给模型一个错的数字）。
2. **绝不放大**。两道闸：比例闸（默认 3%，按文本部分算）先滤掉不值得动手的；净收益闸再要求
   省下的 token 必须大于新增标记的开销。任何一步抛错都只写一条 warn，然后返回上游的原始决定。
3. **报错结果一个字都不动**（默认）。报错上下文最贵，`compressErrors` 可以显式打开。

`test/invariant.test.js` 把这些承诺钉成了回归测试，直接跑 `tools/corpus.mjs` 的全套语料
（含真实抓取的输出）逐条核对。

## 实测

### 真实语料（`node tools/real-corpus.mjs`）

语料是本机 **25 个真实会话、2596 条真实工具结果**（`tools/extract-corpus.mjs` 从
`~/.dsh/sessions` 里解出来的），基线 **123 万估算 token**。

| 档位 | 省 | 整行真丢 | 结构完整的源码被裁坏 |
|---|---:|---:|---:|
| 更狠（`500` + `keepRatio 0.35`） | 45.0% | 15 | 11 / 18 |
| **出厂默认（`500` + `0.45` + 回指）** | **44.0%** | **10** | 11 / 18 |
| 质量优先（`800` + `0.45` + 回指） | 37.3% | **2** | 8 / 18 |
| 关掉回指（对照上一版） | 45.9% | 16 | 12 / 18 |

出厂默认按"极致省量"定；**要质量优先就把 `ratioFloorTokens` 设成 800** —— 整行真丢从
10 条降到 **2 条**。

对照：同类工具 `dsh-tool-token-optimizer` 省 **70.1%**、信号丢失 141 条；本插件省 **44.8%**、
信号丢失 133 条，逐条比大小 **449 : 424**（略占优）。

### 省量归因（`node tools/profile-savings.mjs`）

压缩后剩下的内容里：**84.3% 是唯一内容**（读文件、看文档、查 schema，没有重复可折），
**8.1% 是散落重复的整行**（已由回指处理），**7.6% 是同模板值不同的行**。

按形态：

| 内容形态 | 条数 | 剩余 token |
|---|---:|---:|
| `plain`（普通文本/源码） | 1473 | 约 22 万 |
| `json-like` | 206 | 约 19 万 |
| `numbered`（带行号源码） | 237 | 约 10 万 |
| `has-long-line`（含超长单行） | 82 | 约 3.6 万 |

### 回指：散落重复行不丢内容，只留桩

同一行出现在结果的两处、中间隔着别的内容时，连续折叠帮不上忙。做法是给第一次出现的地方
在行尾挂桩 `[D1]`，之后每处只留 `[D1] same as above`——**内容没丢**，照桩号就能找到原文。

```
function load0() {
  const resolvedConfigurationPath = join(configRoot, process.env.DSH_PROFILE ?? "desktop") [D1]
  return 0
}
function load1() {
[D1] same as above
  return 1
}
```

两条踩出来的边界：

- **必须先数一遍出现次数**，只给真的会重复的行挂桩。早期版本给所有够长的行都挂桩，
  那些只出现一次的行白搭一个桩——实测 `git status` 那条被撑大 5 个字符，
  "结果永远不变大"这条不变量直接破了。
- **正文要比桩 + 回指标记长**，否则加桩是亏的。门槛扫描（`backrefMinChars`）：
  48 → 省 44.1% / 整行丢 10；80 → 44.8% / 12；160 → 45.7% / 16。**48 是甜点。**

### 试过但**按实测否掉**的能力

- **注释压缩**（折掉散文注释、保留 `@param`/`TODO`/警告）：真实语料里源码的 26% 是注释，
  听着很值。**实测开着反而比关着多 5416 token**（610033 vs 604617）：折掉注释省下的量，
  抵不过它改变结构后预算与按比例压少压的部分。留成可选（`commentMinBlockChars`），默认关。
- **行内空白压缩**（缩进折成 1 空格/级、行内连续空格收成 1 个）：合计只占剩余 token 的
  **1.2%**（约 8000 token），不值得为它增加一层改写。
- **`#` 开头的行当注释块**：把 `cordis`、`cordis-plugin-group` 这种清单折了。现在只认
  `/** … */` 且必须闭合。
- **跨调用全局去重**：真实语料里重复调用只占 **1.9%**，空间本来就小。

### 硬上界

单条结果**最多**占该工具的 token 预算。真实语料实测 **约 1%** 超出，最坏 4.4 倍——都是
"装不进预算又没法切"的内容（例如已经压成一行的超大 JSON）。修之前这个数字是 **20 倍**。

为此做了六件事，每一件都是踩坑之后补的：

1. **超长行先拆成有结构的单元**。4 万字符的单行既装不进预算（实测 20 倍超标）也不能整条丢
   （信息全丢）。拆点优先选 JSON 字段边界，其次句末，最后才按宽度切。
2. **省略标记也算字符**。一整段丢掉会生成一个标记行，几百个缺口就是几百个标记。
3. **有信息量的行不许切**。状态标记 / 报错 / 警告行只参与"整行取舍"，永远不切。
4. **结构行不许丢**。`}` / `);` / 以括号开头的骨架行——本身几乎不含信息，但丢了它们，
   剩下的代码看起来就是坏的。
5. **折叠要留变体样本**。20 个不同的错误码全折成一个 `×20` 会丢掉类型差异——现在保留前几个
   内容不同的行（报错类留 5 个、普通日志留 3 个）。
6. **收口要量成品**。选择器按估算预留标记开销，实测预算 6000 时成品 7059。现在渲染出来
   量一遍，超了按比例收每一行。

### 报错识别（这一条修得最值）

报错前缀正则在 1.3.1 之前用的是 `^\s*ERROR\b` ——**锚定行首**。真日志长这样：

```
2026-01-01 10:01:37 ERROR upstream returned 503 for /api/item/97
```

`ERROR` 前面有时间戳，`^` 匹配不到 → 被判成普通行 → 预算裁剪时挤掉。
也就是说"报错不许被静默挤掉"这条承诺，在**最典型的日志输入上从来没生效过**。
改成 `(?:^|\s)` 之后，`ERROR` / `npm ERR!` / 堆栈帧 / `WARN` 才真正被当成高优先级。

### 摘要点名

被丢掉的中段会生成一行摘要，点名里面还有哪几类东西：

```
[… 3 path lines (e.g. /tmp/a/b/c.js) — elided, not code]
[… 1 error (e.g. ERROR: boom); 1 warning (e.g. WARN: careful) — elided, not code]
```

只报一个数字，模型无法判断要不要回读；说清类型与例子，一行就够。
摘要插在**末段之前**——末行是"最后发生了什么"，必须留在最后。

### JSON 的特殊处理

- **键重复的对象数组 → 表**：`{"_columns":[...], "_rows":[[...]]}`。真实语料里这类有
  2176 行、32.4 万字符。仍是合法 JSON，内容一个不丢。单条实测 94 行对象 9466 → 3134 字符。
- **压成一行后不再切行**（切了整段就不再合法 JSON）。
- **压成一行仍装不下时**从末尾截断并写明省了多少
  （`… (134391 chars omitted from the end of this JSON)`），而不是按行丢——按行丢会丢掉
  `},` 这类行，整段立刻 `Expected double-quoted property name`。

### 幂等

连压三次，第二次与第三次的**长度完全一致**（0 条漂移）。带本插件标记的内容不再做结构压缩、
不再按比例压、不再套预算、也不收口——早期版本会 6629 → 5399 → … 一路把上下文吃光。
另外"带标记的行不参与折叠"：一条 `… ×N` 代表多行原文，折进另一个标记会真的吃掉内容。

### 性能与健壮性

- **延迟**：p50 `0.06ms`、p90 `0.8ms`、p99 `5.8ms`、最慢 `46ms`（5 万字符输入）。
  2596 条整批处理 1.2 秒。
- **对抗性输入**（空串、200KB 单行、纯 ANSI、20 万 base64、未闭合 JSON、全 emoji…）：
  **0 抛错、0 放大**。
- **闸门**：错误结果 / 开关关闭 / 太短 / 黑名单工具 / 二进制 / 纯富内容块 —— 全部逐字透传。
- **不变量**：虚报省略行数 **0**、结果变大 **0**、幂等漂移 **0**。

### 合成语料（`node tools/bench.mjs`）

| 语料 | 类型 | 估算 token | 省 |
|---|---|---:|---:|
| 500 行运行日志 | log | 7016 → 837 | 88.1% |
| 构建 + 测试产出 | build | 383 → 40 | 89.6% |
| `git status`（68 文件） | status | 500 → 69 | 86.2% |
| 400 行 `ls -l` | listing | 6073 → 1502 | 75.3% |
| 6 文件 unified diff | diff | 2032 → 519 | 74.5% |
| 150 项嵌套 JSON | json | 10092 → 4951 | 50.9% |
| 600 行带行号源码 | numbered-source | 6519 → 4034 | 38.1% |

**这两张表说的都是"压缩器能省多少"，不等于任务总 token 的节省。** 总账还取决于工具调用
的次数与分布、模型重复读不读同一个东西、有多少内容压根不走工具。

复现：

```bash
node --test "test/*.test.js"     # 89 个用例
node tools/bench.mjs             # 合成语料 + 三条不变量
node tools/real-corpus.mjs       # 真实语料 + 与同类工具对照
node tools/sweep-budget.mjs      # 预算扫描
node tools/gate.mjs              # 净收益门槛扫描
```

## 安装

### 装进某个 profile

```bash
# 1) 把插件加进 profile 的依赖（用 link: 指向本仓库目录）
cd <DSH_HOME>/profiles/<profile名>
#    在 package.json 的 dependencies 里加一行：
#      "dsh-meta-optimizer": "link:/绝对路径/dsh-meta-optimizer"
pnpm install

# 2) 重启该 profile（DSH Desktop 需要重启应用；profile 的插件行在启动时装载）
```

插件自带 `cordis.patch.yml`（`dsh.bundle.patch` 指向它），因此安装后会自动插入
`id: context-guard` 这一行。也可以在 `cordis.patch.yml` 里自己加：

```yaml
- insert:
    - id: context-guard
      name: 'dsh-meta-optimizer'
      config:
        enabled: true
        incremental: delta
        budgetChars: 12000
```

### 卸载

从 profile 的 `package.json` 依赖里删掉那一行，`pnpm install`，再删掉 patch 里的插入行，
重启。插件不写任何全局状态。

## 配置

全部可省略；写错键名会**当场报错**（不会静默失效）；校验失败会退回全默认。

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关。关掉后监听器立刻变直通，不产生任何额外 token |
| `budgetTokens` | `1500` | 单结果 **token** 预算（每工具另有预设；显式设的全局值优先） |
| `toolBudgets` | `{}` | 按工具覆盖预算（token），例如 `{ bash: 800 }` |
| `minChars` | `200` | 小于这个字符数的结果完全不处理 |
| `minSavingRatio` | `0.03` | 省不到这个比例就不改（另有净收益兜底） |
| `keepRatio` | `0.45` | **省量的主旋钮**：按比例压到几成；设 0 只压确定冗余的部分 |
| `minKeepTokens` | `200` | 按比例压时的最少保留 token |
| `incremental` | `'delta'` | `off` / `identical` / `delta` |
| `incrementalMinChars` | `600` | 进入增量比对的最小字符数 |
| `memoryEntries` | `64` | 增量记账表容量 |
| `repeatRun` | `3` | 连续重复行折叠阈值 |
| `repeatMinLength` | `24` | 全文去重的行长度下限 |
| `repeatMinSaved` | `64` | 全文去重的省量下限 |
| `diffContext` | `3` | diff 每个变动点前后保留几行上下文 |
| `maxBlankRun` | `1` | 连续空行最多保留几行 |
| `jsonIndent` | `0` | JSON 缩进字符数；0 = 压成一行 |
| `conservative` | `false` | 只做无损规范化，不做结构改写（排错档） |
| `compressErrors` | `false` | 报错结果是否也压缩 |
| `skipTools` | `[]` | 不处理的工具名 |
| `log` | `false` | 打印每次压缩的明细 |

按工具名的默认预算（token）：`web_fetch` 2500、`read` 2000、`bash`/`task`/`workflow` 1500、
`univer` 1400、`grep`/`web_search` 900、`glob`/`list` 600。带"全文已存到溢写文件"提示的结果
另有更狠的一档（350 token）——全文在文件里，压短不是丢信息。
`read` / `write` / `edit` 属于"高风险内容"，只做规范化 + 去重 + 预算，不做任何结构改写。

### 装载与运行留痕

插件会往 `<DSH_HOME>/context-guard.trace.jsonl` 追加两种记录（只记事实，**不记任何结果内容**）：

```json
{"event":"apply","postExecuteListener":true,"webServer":"registerable","config":{...}}
{"event":"optimized","tool":"bash","steps":["normalize","log-fold"],"charsBefore":14292,"charsAfter":85,"tokensSaved":3551}
```

`event: apply` 出现就说明插件被装载了；`webServer` 字段说明统计端点能不能挂上。写失败一律静默。

**为什么要有这个**：Electron 宿主把插件的 stderr 吞掉了，界面上也不显示装载失败。排查"插件到底有没有被装载"时，
`dsh --profile <profile> headless "任意一句话"` 是唯一能把 `dsh: warning: N entry did not activate` 加完整堆栈
打到终端上的办法；trace 文件则是在桌面端也能看的第二只眼睛。

### 只读诊断端点

装了 `webServer` 时会挂一个 `/dsh-meta-optimizer/stats`，回 JSON：看了多少条结果、改了多少条、
增量命中多少次、回滚多少次、累计省了多少估算 token、各步骤与各类型的命中次数。不返回任何
结果内容。

## 与其它插件的关系

- **`dsh-tool-token-optimizer`**：它挂在同一个 `tools/post-execute` 上做"头 + 尾 + 报错行"
  的预算裁剪。两者叠加不会出错（本插件对同一条结果幂等，且总量自校验），但**会互相看不到
  对方的账**，压出来的效果也不是简单相加。建议二选一：
  - 想要"按信息量挑选 + 类型感知压缩 + 跨调用增量" → 用本插件；
  - 只想保留它已经调好的行为 → 把本插件的 `enabled` 设为 `false`。
- **`dsh-ops`**：优化输入侧（schema / 提示词）并提供 bash 与 Rust 工具，与本插件不冲突。

## 代码结构

```
lib/units.js     单位与标记：每条"输出行"自带"它代表几行原文"，收尾自校验
lib/text.js      无损规范化（ANSI、\r、不可见字符、空白形状、指纹）
lib/detect.js    内容类型识别（识别不出就不上结构化压缩）
lib/compact.js   结构化压缩器（diff / status / listing / tree / gutter / log / build / 去重）
lib/budget.js    打分与预算内取舍；JSON 紧凑化
lib/replay.js    跨调用增量（记账表、前缀+后缀差分、渲染）
lib/policy.js    流水线编排 + 净收益闸门 + 标记渲染与对账
lib/schema.js    配置校验（Standard Schema v1，未知键拒绝）
lib/index.js     宿主插件层（tools/post-execute 注册、统计、诊断端点）
tools/corpus.mjs 语料生成器（含真实抓取的输出）
tools/bench.mjs  基准 + 三条不变量自查
```

设计上只有一条主线：**先识别、再动手；动过就必须能说清动了什么；说出来的数字必须能对上账。**

## 已知边界

- 只处理 `text` 块。图片、文件、结构化块原样保留（它们计入净收益总账，但不会被改写）。
- 检测是启发式的：识别错类型最多导致"压得少"，不会压坏——每种压缩都只做它明确定义的
  那几件事，且总量自校验会兜底。
- 跨调用增量假设"上一次的结果仍在上下文里"。如果模型侧发生了上下文裁剪，模型可能看不到
  被引用的内容。真遇到这种场景，把 `incremental` 设为 `off` 即可。
- 增量记账按"工具名 + 参数"在进程内保留最近 64 条；重启进程即清空。
