# dsh-context-guard

**输出前压缩**：工具结果在写进上下文**之前**再过一道压缩关卡。类型感知的结构化压缩 +
跨调用增量 + 预算内按信息量取舍，每一步都可解释、可关闭，而且**只有真省了才动手**。

> 与 [`dsh-ops`](https://github.com/T-Auto/dsh-ops) 的关系：dsh-ops 主要优化**输入侧**
> （把工具 schema、描述、系统提示词压短），并明确不做调用级去重。本插件在**输出侧**——
> 也就是"结果已经产生、token 还没付"的那一刻——做结构化压缩与跨调用增量，两者互补，
> 互不冲突（但注意：本插件与 `dsh-tool-token-optimizer` 作用在同一钩子上，建议二选一，
> 见下文「与其它插件的关系」）。

---

## 它站在哪里

挂在宿主公开契约 **`tools/post-execute`** 瀑布钩子上：工具已经跑完、结果还没写进会话与
请求的那一瞬间。

只挂这一个钩子，而且**根上挂一次就够**：`tools/post-execute` 是带作用域的事件，由
`ToolRuntime` 用 `scopeTarget(this, exec.agent)` 派发；作用域事件的路由规则是"无标签监听器
放行、有标签监听器只在标签是分发键或其祖先时放行"。因此根上这一个不带标签的监听器会收到
**所有** agent、所有会话、所有嵌套子调用（含 PTC / `run_code` 内部）的结果，不需要按 agent
各注册一份，也就不会随 agent 数量增长。

不包模型调用、不改模型目录、不碰工具注册表、不加系统提示词——**受影响的只有结果文本**。

## 三级流水线

### 1. 无损规范化（永远先跑，永远安全）

| 做什么 | 为什么 |
|---|---|
| 剥 ANSI 颜色 / 光标序列 | 终端上色只对人有用；带光标左移的序列按"终端最终可见的那一行"还原 |
| `\r` 覆盖式进度条收敛成最终一行 | `\r45%\r100% done` 只需最后一次 |
| 统一不可见字符（NBSP、零宽、BOM、方向控制符） | 不占视觉宽度，只白烧 token |
| 去行尾空白 / 压 3 行以上的连续空行 / 去首尾空行 | 纯形状 |
| 4 个以上的同字符空格串压到 2 个 | 生成出来的填充；1-3 个空格的真对齐不动 |

刻意**不做**：不把制表符换成空格、不重排缩进、不删行内空格、不合并"有内容的重复行"——
那些都会改语义（源码、`ls -l` 对齐全靠它）。

### 2. 类型感知的结构化压缩（识别不出类型就不上）

先识别、后压缩。识别不出来的内容只走第 1 级 + 第 3 级，绝不上结构化改写。

| 类型 | 怎么压 |
|---|---|
| **JSON** | 解析后重新紧凑化：去掉缩进阶梯，短容器内联。键、值、顺序一个不变 |
| **unified diff** | 每个文件的头折成一行 `# path (+a/-b)`；**增删行全部保留**（那是 diff 的全部价值）；超出的上下文行折成 `… (N lines unchanged context)`；`\ No newline at end of file` 折进上一行 |
| **git status** | 同状态的文件合并成一行，去掉逐行的 `(use "git ...")` 提示；被合并的行数记在单位上，"一共多少个文件"仍然可数 |
| **文件清单 / 目录树** | `ls -l` 权限列全一致时压掉权限列并写明；`├──`/`└──` 画线前缀压成纯缩进 |
| **带行号源码** | 行号列压到最小宽度并对齐。**代码一个字符都不动** |
| **日志** | 连续的"同一模板、只有时间戳/数字不同"的行折成 `首行 …×N (same event repeated; last: <最后一次的值>)` |
| **构建 / 测试产出** | 只有**没有任何失败信号**时才折进度行；一旦出现 error/fail/ERR 就整段不动 |
| **源码** | 只折叠"连续 3 行以上完全相同"的重复行 |
| **其它** | 折叠同一行第 3 次及以后的出现（折掉的总字符数要够本才折） |

### 3. 预算内按信息量取舍（压不下去时才砍）

超过预算（默认 12000 字符，按工具名另有默认）时，不再"取前 N 行 + 后 N 行"，而是给每一行
打分后在预算内挑选：

- **加分**：报错、失败、异常、堆栈、`expected/actual`、`:行:列`、文件路径、`exit code`、
  `not found`/`permission denied`、hunk 头、测试汇总；
- **减分**：空行、版权声明、`Please/Note/Hint` 提示、纯链接；
- 永远保留开头 6 行与结尾 8 行（命令、表头、结论、汇总都在两头）；
- 每个缺口写成 `… (N lines omitted, low-signal lines dropped)`。

### 4. 跨调用增量

同一个"工具名 + 参数"的输出第二次出现时，旧内容**还在上下文里**，再贴一遍是纯重复付费：

- 完全一样 → 一行 `(unchanged: byte-identical to the previous result of this same call, N lines, <hash>)`；
- 只是追加或局部改动 → `(delta vs the previous result of this same call: N lines unchanged)` +
  没变的只报数、变动的**逐字**给出（`- 旧行` / `+ 新行`）；
- 变化超过 40% → 照原样返回，不做增量。

模式可选：`delta`（默认）/ `identical`（只认完全相同）/ `off`。

## 三条绝不越界的承诺

1. **绝不静默丢信息**。任何"少了行"的地方都留下标记，写清楚少了几行。标记里的数字经过
   *自校验*：每个单位自带"它代表几行原文"，收尾时做加法；总量对不上就整条回滚成原文
   （宁可这一条不省，也不给模型一个错的数字）。
2. **绝不放大**。省不到 `minSavingRatio`（默认 12%）或结果反而变大 → 回滚成原文。任何一步
   抛错都只写一条 warn，然后返回上游的原始决定。
3. **报错结果一个字都不动**（默认）。报错上下文最贵，`compressErrors` 可以显式打开。

`test/invariant.test.js` 把这些承诺钉成了回归测试，直接跑 `tools/corpus.mjs` 的全套语料
（含真实抓取的输出）逐条核对。

## 实测（本机语料，`node tools/bench.mjs`）

估算口径与 DSH 官方一致（UTF-16 字符数 / 4 向上取整 + 每块 4 开销）。

| 语料 | 类型 | 估算 token | 省 | 不变量 |
|---|---|---:|---:|---|
| 600 行带行号源码 | numbered-source | 6519 → 4034 | 38.1% | 通过 |
| 6 文件 unified diff | diff | 2032 → 519 | 74.5% | 通过 |
| 400 行 `ls -l` | listing | 6073 → 1502 | 75.3% | 通过 |
| 500 行运行日志 | log | 7016 → 837 | 88.1% | 通过 |
| 构建 + 测试产出 | build | 383 → 40 | 89.6% | 通过 |
| 150 项嵌套 JSON | json | 10092 → 4951 | 50.9% | 通过 |
| `git status`（68 个文件） | status | 500 → 69 | 86.2% | 通过 |
| 目录树（25 个目录） | tree | 687 → 369 | 46.3% | 通过 |
| 重复堆栈 ×40 | log | 3270 → 1343 | 58.9% | 通过 |
| 4 份真实抓取输出 | real | 2489 → 2343 | 5.9% | 通过 |
| **合计** | | **39135 → 16647** | **57.5%** | **0 条不变量失败** |

**这些数字只说明"压缩器在真实形状的语料上能省多少"，不等于任务总 token 的节省比例。**
总账还取决于：工具调用的次数与分布、模型的重复读取习惯、上下文命中缓存的价格、
以及会话里有多少内容根本不经工具产生。真实抓取的小文件（几百字节到几 KB）省得很少，
因为规范化本身就没多少可去——这是正常的，也正是"净收益闸门"该拦住的那类。

复现：

```bash
node --test "test/*.test.js"   # 84 个用例
node tools/bench.mjs           # 上面这张表
node tools/bench.mjs --json    # 同样数据，机器可读
```

## 安装

### 装进某个 profile

```bash
# 1) 把插件加进 profile 的依赖（用 link: 指向本仓库目录）
cd <DSH_HOME>/profiles/<profile名>
#    在 package.json 的 dependencies 里加一行：
#      "dsh-context-guard": "link:/绝对路径/dsh-context-guard"
pnpm install

# 2) 重启该 profile（DSH Desktop 需要重启应用；profile 的插件行在启动时装载）
```

插件自带 `cordis.patch.yml`（`dsh.bundle.patch` 指向它），因此安装后会自动插入
`id: context-guard` 这一行。也可以在 `cordis.patch.yml` 里自己加：

```yaml
- insert:
    - id: context-guard
      name: 'dsh-context-guard'
      config:
        enabled: true
        incremental: delta
        budgetChars: 12000
```

### 卸载

从 profile 的 `package.json` 依赖里删掉那一行，`pnpm install`，再删掉 patch 里的插入行，
重启。插件不写任何全局状态。

## 配置

全部可省略；写错键名会**当场报错**（不会静默失效）；校验失败会退回全默认。

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关。关掉后监听器立刻变直通，不产生任何额外 token |
| `budgetChars` | `12000` | 单结果字符预算兜底值 |
| `toolBudgets` | `{}` | 按工具覆盖预算，例如 `{ bash: 4000 }` |
| `minChars` | `400` | 小于这个字符数的结果完全不处理 |
| `minSavingRatio` | `0.12` | 省不到这个比例就不改 |
| `incremental` | `'delta'` | `off` / `identical` / `delta` |
| `incrementalMinChars` | `600` | 进入增量比对的最小字符数 |
| `memoryEntries` | `64` | 增量记账表容量 |
| `repeatRun` | `3` | 连续重复行折叠阈值 |
| `repeatMinLength` | `24` | 全文去重的行长度下限 |
| `repeatMinSaved` | `64` | 全文去重的省量下限 |
| `diffContext` | `3` | diff 每个变动点前后保留几行上下文 |
| `maxBlankRun` | `1` | 连续空行最多保留几行 |
| `jsonIndent` | `0` | JSON 缩进字符数；0 = 压成一行 |
| `conservative` | `false` | 只做无损规范化，不做结构改写（排错档） |
| `compressErrors` | `false` | 报错结果是否也压缩 |
| `skipTools` | `[]` | 不处理的工具名 |
| `log` | `false` | 打印每次压缩的明细 |

按工具名的默认预算：`read` 16000、`web_fetch` 14000、`bash`/`task`/`workflow` 12000、
`univer` 10000、`grep`/`web_search` 8000、`glob`/`list` 6000。
`read` / `write` / `edit` 属于"高风险内容"，只做规范化 + 去重 + 预算，不做任何结构改写。

### 只读诊断端点

装了 `webServer` 时会挂一个 `/dsh-context-guard/stats`，回 JSON：看了多少条结果、改了多少条、
增量命中多少次、回滚多少次、累计省了多少估算 token、各步骤与各类型的命中次数。不返回任何
结果内容。

## 与其它插件的关系

- **`dsh-tool-token-optimizer`**：它挂在同一个 `tools/post-execute` 上做"头 + 尾 + 报错行"
  的预算裁剪。两者叠加不会出错（本插件对同一条结果幂等，且总量自校验），但**会互相看不到
  对方的账**，压出来的效果也不是简单相加。建议二选一：
  - 想要"按信息量挑选 + 类型感知压缩 + 跨调用增量" → 用本插件；
  - 只想保留它已经调好的行为 → 把本插件的 `enabled` 设为 `false`。
- **`dsh-ops`**：优化输入侧（schema / 提示词）并提供 bash 与 Rust 工具，与本插件不冲突。

## 代码结构

```
lib/units.js     单位与标记：每条"输出行"自带"它代表几行原文"，收尾自校验
lib/text.js      无损规范化（ANSI、\r、不可见字符、空白形状、指纹）
lib/detect.js    内容类型识别（识别不出就不上结构化压缩）
lib/compact.js   结构化压缩器（diff / status / listing / tree / gutter / log / build / 去重）
lib/budget.js    打分与预算内取舍；JSON 紧凑化
lib/replay.js    跨调用增量（记账表、前缀+后缀差分、渲染）
lib/policy.js    流水线编排 + 净收益闸门 + 标记渲染与对账
lib/schema.js    配置校验（Standard Schema v1，未知键拒绝）
lib/index.js     宿主插件层（tools/post-execute 注册、统计、诊断端点）
tools/corpus.mjs 语料生成器（含真实抓取的输出）
tools/bench.mjs  基准 + 三条不变量自查
```

设计上只有一条主线：**先识别、再动手；动过就必须能说清动了什么；说出来的数字必须能对上账。**

## 已知边界

- 只处理 `text` 块。图片、文件、结构化块原样保留（它们计入净收益总账，但不会被改写）。
- 检测是启发式的：识别错类型最多导致"压得少"，不会压坏——每种压缩都只做它明确定义的
  那几件事，且总量自校验会兜底。
- 跨调用增量假设"上一次的结果仍在上下文里"。如果模型侧发生了上下文裁剪，模型可能看不到
  被引用的内容。真遇到这种场景，把 `incremental` 设为 `off` 即可。
- 增量记账按"工具名 + 参数"在进程内保留最近 64 条；重启进程即清空。
